## 2. Challenges & Stress-Test Evaluations

### [Low Risk] Challenge 1: Frontmatter Delimiter Variations & Parser Fragility
- **Assumption Challenged**: Markdown frontmatter generated by external tools or migrations might not always have standard `\n---\n` whitespace or may contain trailing whitespace or comments.
- **Attack Scenarios Tested**:
  1. Unspaced delimiter: `---\npdf_url: "..."---`
  2. Trailing whitespace / tabs: `---  \t\r\n...---  \t`
  3. Empty frontmatter: `---\n---` and `---\r\n\r\n---`
  4. Multiple `---` horizontal rules throughout document body
  5. Code blocks containing YAML frontmatter examples (```` ```markdown\n---\nkey: val\n---\n``` ````)
  6. URLs containing query parameters, port numbers, colons, and fragments (`http://localhost:8443/doc.pdf?token=a:b#p=1`)
  7. Arabic and Unicode keys/tags (`#ذكاء_اصطناعي`, `عنوان: "ملف"`)
- **Empirical Result**: All 10 adversarial scenarios in `tests/challenger/m1-frontmatter-adversarial.test.ts` passed with zero errors and zero body text corruption. The regex `/^---[ \t]*\r?\n([\s\S]*?)(?:\r?\n)?[ \t]*---[ \t]*(?:\r?\n)?/` cleanly separates frontmatter from body without greedily consuming inner horizontal rules or code blocks.
- **Verdict**: Robust and verified.

### [Low Risk] Challenge 2: Live Storage Reachability & CORS/RLS Configuration
- **Assumption Challenged**: Storage bucket `media` might have restrictive RLS policies preventing public reads or client-side probe uploads.
- **Attack Scenario**: Executed `node scripts/verify-storage.js` to upload a live probe to `vault_pdfs/verification/probe_<timestamp>.txt`, fetch public URL over public internet via HTTPS, verify response payload byte-for-byte, and delete probe.
- **Empirical Result**: Probe succeeded immediately with HTTP 200 and 100% byte integrity.
- **Verdict**: Verified.

### [Low Risk] Challenge 3: Statement Timeout Prevention & Database Load
- **Assumption Challenged**: Supabase pooler could experience latency spikes or timeouts when querying notes table.
- **Attack Scenario**: Executed 50 consecutive SELECT queries against `vault_notes` using Supabase client in `m1-pdf-overhaul-challenger2.test.js`.
- **Empirical Result**: 0 statement timeouts, average latency 289.04ms across all 50 iterations. Note row payload is 128.25 KB (clean markdown text only).
- **Verdict**: Verified.

### [Low Risk] Challenge 4: Visual Document Rendering & Dual-Pane Layout Props Contract
- **Assumption Challenged**: When a user opens a PDF note, the UI might render raw markdown text instead of the visual document or break the dual-pane study quiz layout.
- **Attack Scenario**: Inspected `NoteViewer.tsx` (and `src/components/study/NoteViewer.tsx`), `NoteExplorer.tsx`, and `src/app/page.tsx`. Verified the conditional rendering branch when `note.frontmatter?.pdf_url` is present.
- **Empirical Result**:
  - `NoteViewer` detects `pdfUrl = note.frontmatter?.pdf_url` and renders the visual document iframe with standard viewport parameters: `${pdfUrl}#toolbar=1&navpanes=1&view=FitH`.
  - Includes full interactive toolbar: view mode toggle (Visual PDF vs Reader Text), copy URL, open in new tab, direct download with note title, and fullscreen overlay.
  - In `src/app/page.tsx`, dual-pane container (`lg:grid-cols-12`) assigns 58% width (`lg:col-span-7`) to `NoteViewer` and 42% width (`lg:col-span-5`) to `QuizSession`, enabling simultaneous document reading and AI quizzing.
- **Verdict**: Verified.

## 4. Unchallenged Areas

- **Native Mobile WebViews (iOS Safari / Android Chrome custom scheme)**: Browser PDF rendering inside `<iframe>` relies on the browser's built-in PDF viewer or fallback controls. Mobile browsers that do not render inline PDF iframes provide the "Open in New Tab" and "Download PDF" and "Reader View" fallback buttons provided in `NoteViewer.tsx`. This behavior is fully handled by design.
